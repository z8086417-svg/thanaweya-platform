# منصة مدرسين الثانوية العامة — نموذج تجريبي (Prototype)

نموذج شغال لمنصة تجمع مدرسين الثانوية العامة، كل مدرس له مساحة برفع فيها دروسه،
ومساعد ذكاء اصطناعي خاص بيه بيجاوب الطلاب من نفس محتواه فقط (مش من الإنترنت
عامةً)، ومساعد تاني بيولّد للمدرس امتحانات وملخصات من دروسه في ثواني.

## الحزمة التقنية (Stack)
- **Backend**: Python + Flask (بسيط، سهل الفهم والتعديل)
- **Database**: SQLite (ملف واحد، من غير أي إعداد سيرفر)
- **AI**: Anthropic API (Claude) — مساعد الطالب + توليد الامتحانات/الملخصات للمدرس
- **Frontend**: HTML + Jinja2 + JS بسيط (من غير أي framework تاني، عشان تشغيل سريع)

## التشغيل

```bash
cd thanaweya-platform
pip install -r requirements.txt

# لازم مفتاح Anthropic API عشان الذكاء الاصطناعي يشتغل فعليًا
export ANTHROPIC_API_KEY=sk-ant-...      # macOS/Linux
# set ANTHROPIC_API_KEY=sk-ant-...       # Windows (cmd)

python app.py
```

افتح المتصفح على: **http://localhost:5000**

أول تشغيل بيعمل قاعدة بيانات `platform.db` تلقائيًا فيها 3 مدرسين تجريبيين
(رياضيات، فيزياء، لغة عربية) وكل واحد معاه دروس جاهزة عشان تجرب على طول.

من غير `ANTHROPIC_API_KEY` البلاتفورم كلها بتشتغل عادي (تصفح، رفع دروس)،
لكن المساعد الذكي وتوليد الامتحانات هيردوا برسالة توضح إن المفتاح ناقص بدل
ما يكسروا.

## صور شخصية لكل الحسابات (جديد)

الطالب، المدرس، وأي حساب إدارة بيقدروا يضيفوا/يغيّروا صورة شخصية:
- الطالب: وقت التسجيل، أو بعد كده من صفحة "حسابي".
- المدرس: من لوحة تحكمه.
- الإدارة: من لوحة التحكم، وكمان الرئيس بيقدر يحط صورة للإداري وهو بيضيفه.

الصور بتتخزن في `uploads/` بأسماء عشوائية (مش اسم الملف الأصلي، لتفادي
تعارض/تخمين الأسماء)، وفيه تحقق من النوع (png/jpg/jpeg/gif/webp بس) وحجم
أقصى 5 ميجا لكل صورة. الملفات المرفوعة بيتم مسحها ضده فيروسات (توقيعات
برمجية خبيثة) والصور بتتعاد ترميزها بمسح ضوئي/برمجي (Pillow) عشان يطلع أي
كود مخفي، وبيتخدم الملفات فقط عبر روت محمي بـ `/uploads/...` بامتدادات
مسموحة — مفيش ملفات تنفيذية أو سكربتات بتتخدم أبدًا. كل حدث أمني بيتسجل في
جدول `audit_log`.

## رسوم بيانية (جديد)

- **عند المدرس:** رسم بياني (Chart.js) في لوحة تحكمه بس، يوضح كام مرة اتفرج
  الطلاب على كل حصة من حصصه هو. كل فتحة لصفحة المدرس بتسجل "مشاهدة" لكل حصة
  مفتوحة للطالب.
- **عند الطالب:** رسم بياني في صفحة "حسابي" يوضح تقريبًا كام ساعة قعد يذاكر
  عند كل مدرس. الحساب مبني على "نبضة" بتتبعت من المتصفح كل دقيقة وهو فاتح
  صفحة المدرس والصفحة ظاهرة (مش تاب تاني أو الشاشة مقفولة) - يعني تقدير
  تقريبي مش تتبع دقيق للتركيز الفعلي.

## فيديو مرفوع على المنصة + وقت مذاكرة دقيق (جديد)

المدرس بقى يقدر يرفع ملف فيديو فعلي (لحد 300 ميجا، mp4/webm/mov) بدل ما
يحط لينك خارجي بس - بيتخزن في `uploads/videos/` ويتعرض بمشغل فيديو
عادي (HTML5) في صفحة الطالب. لو مفيش وقت يرفع فيديو، لسه فيه خيار رابط
خارجي كـ fallback.

**وقت المذاكرة بقى مبني على تقدّم التشغيل الحقيقي مش مجرد فتح الصفحة:**
المشغل بيبعت تقدمه الفعلي (`currentTime`) كل ما يتجمع 10 ثواني تشغيل حقيقي،
والسيرفر بيسقّف كل نبضة عند 20 ثانية عشان محدش يقدر يزوّر رقم كبير من
الـ devtools. يعني لو طالب سايب الفيديو واقف أو التاب مقفول، مفيش وقت
بيتحسب - بعكس وقت التصفح العام (heartbeat) اللي كان بيتحسب لمجرد إن الصفحة
فاتحة وظاهرة.

الرسم البياني في "حسابي" دلوقتي بيجمع الاتنين مع بعض (وقت تصفح عام + وقت
مشاهدة فيديو حقيقي) لكل مدرس.

⚠️ الفيديوهات بتتخزن على قرص السيرفر نفسه - كويّس لبروتوتايب، لكن لحجم
استخدام حقيقي (خصوصًا فيديوهات كتير أو كبيرة) الأفضل تنقلها لتخزين سحابي
(S3, Bunny, Cloudflare R2) بدل قرص السيرفر.

## لوحة تحكم الإدارة (جديد)

فيه أيقونة ⚙️ في أعلى يمين كل صفحة فيها اختصارات لكل شاشات المنصة، من ضمنها
"لوحة تحكم الإدارة" اللي بتعرض نظرة عامة (عدد المدرسين، عدد الدروس، الطلاب
النشطين، إجمالي الإيرادات).

الدخول محمي بباسورد حقيقي (مشفّر، مش زي دخول الطالب/المدرس اللي لسه بالاسم
بس). أول تشغيل بيعمل حساب افتراضي:

- **اسم المستخدم:** `admin`
- **كلمة المرور:** `ChangeMe@2026`

⚠️ **غيّر الباسورد ده قبل أي استخدام حقيقي.** تقدر تحدد حساب مختلف من الأول
لأي بيئة جديدة بمتغيرات البيئة:

```bash
export ADMIN_USERNAME=your_username
export ADMIN_PASSWORD=your_strong_password
```

(لازم تتحط قبل أول تشغيل يعمل فيه قاعدة البيانات - لو غيّرتها بعد كده مش
هتتحدث تلقائي، هتحتاج تعدّل الباسورد من جدول `admins` مباشرة أو تعمل حساب جديد.)

### إضافة مدرس من لوحة الإدارة (جديد - رئيس بس)

الرئيس بس بيشوف قسم "إضافة مدرس" في لوحة تحكمه، بيحدد فيه: اسمه، تخصصه،
شغال فين (سنتر/مدرسة)، رقم موبايله (اختياري)، ونسبة عمولة المنصة من مبيعاته،
وصورة شخصية. النظام بيولّد كود حساب وباسورد للمدرس أوتوماتيك (زي تسجيل
الطالب بالظبط):

- لو حطيت رقم موبايل، البيانات بتتبعت واتساب (بترجع لمحاكاة SMS لو مفيش
  حساب واتساب حقيقي مربوط - شوف قسم "تسجيل ودخول الطالب" تحت لتفاصيل الإعداد).
- البيانات كمان بتتعرض مرة واحدة على شاشة الرئيس نفسه بعد الإضافة مباشرة
  (مفيش رقم موبايل؟ دي الطريقة الوحيدة تعرفها، مش هتتعرض تاني).

اداري (مش رئيس) مايشوفش القسم ده خالص، وحتى لو حاول يستخدم الرابط مباشرة
هيترفض.

### إيقاف/تفعيل الحسابات + البحث بالكود (جديد)

أي حد من فريق الإدارة (رئيس أو اداري) بيقدر:
- يشوف كل الطلاب وكل المدرسين في قسم "🚫 إدارة الحسابات" ويوقف/يفعّل أي
  حساب بضغطة زرار. الحساب الموقوف مايقدرش يدخل تاني (لو داخل فعلاً وقت
  الإيقاف، بيتطرد من أول صفحة يفتحها).
- يدوّر بكود أي حساب (كود الطالب `STU-...`، كود المدرس `TCH-...`، أو اسم
  مستخدم أي حساب إداري) من قسم "🔍 دوّر بالكود" فوق، ويوقفه من نفس مكان النتيجة.
- يغيّر باسورد أي طالب أو مدرس من زرار "🔑 تغيير الباسورد" جنب كل حساب (6
  حروف/أرقام على الأقل).

⚠️ **مش هتلاقي الباسوردات القديمة معروضة حد فيه** - دي مش قصور في الميزة،
دي نقطة أمان أساسية: الباسوردات متخزنة مشفّرة باتجاه واحد (hashing)، ومفيش
طريقة تقنية ترجعها لنص عادي - حتى النظام نفسه مايقدرش. ده نفس اللي بيحصل في
أي نظام حقيقي (جوجل، فيسبوك...)؛ الحل العملي دايمًا هو "غيّر الباسورد"
مش "اعرض الباسورد القديم".

### وقت دخول محدد للإداري (جديد - رئيس بس)

الرئيس بيقدر يحدد "من الساعة - لحد الساعة" (بنظام 24 ساعة) لأي حساب اداري
وهو بيضيفه، فمايقدرش يدخل المنصة إلا في المواعيد دي. اتركهم فاضيين لو عايز
دخول بلا قيد وقت. الرئيس نفسه دايمًا من غير قيد وقت.

## امتحاناتي وواجباتي (جديد)

شاشتين جديدتين للطالب:
- **📝 امتحاناتي:** كل الامتحانات المتاحة ليه من كل المدرسين اللي مشترك
  معاهم (مش مدرس واحد بس).
- **📔 واجباتي:** كل الواجبات المتاحة ليه، وحالة كل واحد (لسه ماسلّمش /
  مسلّم وبينتظر تصحيح / اتصحح ومعاه الدرجة والملاحظات) في مكان واحد.

كمان صفحة "حسابي" بقى فيها إحصائية "مشترك مع كام مستر" - عدد المدرسين
المختلفين اللي الطالب فعليًا اشترى منهم حاجة أو كلّم مساعدهم الذكي.

## مدة إتاحة مشاهدة الحصة (جديد)

المدرس بيقدر يحدد مدة إتاحة بالأيام (من 3 لـ 14 يوم) لأي حصة وهو بيضيفها -
تتحسب من وقت الشراء. لما المدة تخلص، الحصة بترجع تتقفل تلقائيًا وتظهر
للطالب رسالة إن مدة المشاهدة انتهت، مع خيار يشتريها تاني (الشراء الجديد
بيجدد المدة من تاني). لو المدرس سايب الخانة فاضية، الوصول بيفضل دائم زي
ما كان.

## تسجيل ودخول الطالب (جديد)

بقى فيه تسجيل حقيقي بدل الدخول بالاسم بس. الطالب بيسجل ببياناته (اسمه، اسم
ولي الأمر ومهنته، رقم موبايله ورقم موبايل ولي الأمر، الرقم القومي، وإيميل
جوجل)، والنظام بيديله **كود حساب فريد** (زي `STU-4821`) وباسورد عشوائي.

⚠️ **إرسال الباسورد بواتساب محاكاة دلوقتي** - مش متبعت فعليًا، بس بيتسجل في
اللوج (console) وبيتعرض على شاشة التسجيل مباشرة. الكود جاهز يشتغل فعليًا مع
**Meta WhatsApp Business Cloud API** (الرسمي من فيسبوك/واتساب) بمجرد ما تحط:

```bash
export WHATSAPP_PHONE_NUMBER_ID=xxxxxxxxxx
export WHATSAPP_ACCESS_TOKEN=xxxxxxxxxxxxxxxxxxxx
```

عشان تجيبهم: تعمل تطبيق WhatsApp Business على [developers.facebook.com](https://developers.facebook.com)،
تاخد `phone_number_id` و`access_token` دائم، وتستنى موافقة ميتا على أول
رسالة تمبلت (شرط عندهم لأي رسالة أولى لرقم جديد). من غير الاتنين دول، النظام
بيرجع تلقائي لمحاكاة SMS في اللوج عشان التسجيل ميقفش.

## دخول المدرس + فصل الصلاحيات (جديد)

بقى فيه دخول حقيقي للمدرس (كود حساب + باسورد) بدل الاختيار المفتوح اللي كان
موجود. كل مدرس بيقدر يشوف ويعدّل بياناته هو بس - حتى لو حاول يدخل على رابط
داشبورد مدرس تاني مباشرة، هيترفض ويترجّعله لصفحة الدخول.

الصفحة الرئيسية بقت بوابة دخول (مش صفحة تسويقية)، والقائمة (⚙️) بقت واعية
لدور المستخدم: الطالب بيشوف حاجاته بس، المدرس بيشوف "لوحة تحكمي" بس، والإدارة
كمان منفصلة.

**المدرسين التجريبيين التلاتة** (اللي بييجوا مع الـ seed) كل واحد فيهم اتولّدله
كود حساب فريد (`TCH-xxxx`) تلاقيه في جدول `teachers`، والباسورد الافتراضي
لكلهم هو:

```
Teacher@123
```

⚠️ **غيّره لكل مدرس قبل أي استخدام حقيقي** - نفس التنبيه بتاع باسورد الإدارة.
أي مدرس تضيفه بعد كده (مش من الـ seed) هياخد باسورد عشوائي فعلي بيتبعت بواتساب/SMS
بنفس آلية تسجيل الطلاب.

## تحويل رصيد وإهداء حصص وشات بين الطلاب (جديد)

- **💳 تحويل رصيد:** من "حسابي"، الطالب يقدر يحوّل من رصيد محفظته لصاحبه
  بكود حسابه (`STU-...`). بيترفض لو الرصيد مش كفاية، أو الكود غلط، أو حاول
  يحوّل لنفسه.
- **🎁 هدية كل حصتين:** الطالب يكسب هدية مجانية واحدة كل ما يشتري حصتين
  فعليين (بفلوس، مش هدايا واصلاله). الهدية دي يقدر يديها لأي صاحب بكوده -
  **مش لازم يكون هو نفسه اشترى الحصة اللي هيديها** - أي حصة مدفوعة في
  المنصة تصلح. عدد الهدايا المتاحة ظاهر في "حسابي"، وزرار الإهداء موجود
  تحت أي حصة مدفوعة في صفحة أي مدرس (يظهر بس لو عنده هدايا متاحة). كل
  إهداء بيستهلك هدية واحدة من رصيده.
- **💬 شات بين الطلاب:** منفصل تمامًا عن شات المساعد الذكي مع المدرس - طالب
  يفتح محادثة مباشرة مع صاحبه بكوده، ويقدر يشوف كل محادثاته من صفحة "شات مع
  صحابي".

⚠️ الثلاثة فيتشرز دول بيستخدموا **كود الحساب** (مش الاسم) للتعرف على
"الصاحب" - عشان الاسم ممكن يتكرر بين طالبين، لكن الكود دايمًا فريد.

## إعلانات لكل الطلاب (جديد)

أي حد في فريق الإدارة (رئيس أو اداري) بيقدر ينشر إعلان من لوحة تحكمه -
بيظهر لأي طالب داخل على المنصة (مش للمدرسين ولا لغير المسجلين) كـ**رسالة
كبيرة (popup)** أول ما يفتح أي صفحة، ومعاها إيموجي يعبّر عن المناسبة
(🏮 رمضان، 🎉 عيد، 🎊 مناسبة عامة، أو 📢 إعلان عادي). الطالب بيقدر يقفلها
بزرار "✕" أو "تمام"، ومش هتظهر تاني في نفس الجلسة (لحد ما يسجل دخول تاني
من جديد). تقدر تنشر أكتر من إعلان مع بعض، وتوقف/تفعّل أي واحد فيهم في أي
وقت من غير ما تمسحه.

## هيكل الإدارة: رئيس / اداري (جديد)

حسابات الإدارة بقى ليها صلاحيتين:
- **رئيس** - بيشوف كل حاجة، وهو الوحيد اللي بيقدر يضيف حسابات إدارية جديدة
  (قسم "فريق الإدارة" في لوحة التحكم ظاهر ليه بس).
- **اداري** - بيشوف نفس إحصائيات المنصة، بس من غير قدرة يضيف/يشوف حسابات
  إدارية تانية.

أول حساب إدارة بيتعمل (أو أي حساب إدارة موجود من قبل الفيتشر ده) بيبقى
تلقائيًا **رئيس** - لازم حد يبدأ من فوق.

## أنواع الحصص + الواجبات (جديد)

كل حصة بقى ليها نوع: **نص/شرح**، **فيديو** (برابط خارجي)، **امتحان**، أو
**واجب**. الواجب بقى **نظام تسليم وتصحيح حقيقي**:
- الطالب بيكتب إجابته ويسلّمها من صفحة المدرس (تسليم واحد لكل واجب دلوقتي -
  مفيش إعادة تسليم بعد كده، تحسين سهل يتضاف بعدين لو محتاجينه).
- المدرس بيشوف كل التسليمات في لوحة تحكمه ("تسليمات الواجبات")، وبيحط درجة
  وملاحظات.
- الطالب بيشوف درجته وملاحظات المدرس أول ما يتصحح.

الامتحان دلوقتي لسه عبارة عن نص تعليمات بس (زي الواجب من غير تسليم/تصحيح) -
لو عايز نفس نظام التسليم للامتحانات كمان قولّي.

## نظام الشراء والتقييم (جديد)
- كل درس/حصة ممكن يكون له سعر (0 = مجانية). الحصص المجانية تتفتح تلقائيًا.
- الطالب لازم "يشتري" الحصة (شراء وهمي فوري في النسخة دي - من غير بوابة دفع
  حقيقية) عشان يقدر يشوف محتواها الكامل ويقيّمها.
- **مساعد الذكاء الاصطناعي بيجاوب بس من الحصص اللي فتحها الطالب** (مجانية أو
  مشتراة) - عشان محتوى المدرس المدفوع متسربش عن طريق الشات.
- بعد الشراء، الطالب يقدر يدي تقييم (1-5 نجوم) + تعليق، وده بيظهر في:
  - صفحة الحصة نفسها للطلاب التانيين.
  - لوحة تحكم المدرس (عدد الشراء + متوسط التقييم لكل حصة + آخر التعليقات).

2. ادخل `/student` واكتب أي اسم → اختار نفس المدرس → هتلاقي حصة مجانية
   وحصة مدفوعة. جرب تسأل المساعد سؤال عن الحصة المدفوعة قبل الشراء
   (هيقولك إن المحتوى ده مش متاح ليك)، بعدين اشتريها واسأل تاني.
3. بعد الشراء، قيّم الحصة من نفس الصفحة، وشوف التقييم ظاهر في لوحة تحكم
   المدرس.

## أهم حاجات تحتاج تتعمل قبل أي استخدام حقيقي
- **تسجيل دخول حقيقي**: دلوقتي الدخول بالاسم بس من غير باسورد — ده كفاية
  للتجربة بس مش آمن. استخدم Flask-Login أو JWT + تشفير باسورد (bcrypt).
- **كل مدرس يدير حسابه بنفسه**: دلوقتي أي حد يقدر يدخل أي لوحة تحكم مدرس.
  لازم ربط كل مدرس بحساب خاص بيه.

## أول 5 حاجات أنصح تزودها بعد كده
1. ~~بوابة دفع حقيقية~~ — **اتعملت**: Paymob مربوط فعليًا (شوف قسم
   "الدفع الإلكتروني الحقيقي").
2. **تسجيل دخول وباسورد حقيقي** للمدرسين والطلاب (الأهم قبل أي نشر فعلي).
3. **بحث/استرجاع أذكى (RAG حقيقي)**: دلوقتي كل الحصص المفتوحة للطالب بتتبعت
   كاملة كسياق لكل سؤال — ده هيبقى غالي وبطيء لو الطالب عنده حصص كتير مفتوحة.
   تقدر تستخدم embeddings (زي `sentence-transformers` أو Claude embeddings)
   عشان تجيب بس الحصة المرتبطة بالسؤال.
4. **رفع ملفات PDF/صور بدل النسخ اللصق**: المدرسين هيحبوا يرفعوا ملزمة PDF
   أو صورة سبورة بدل ما يكتبوا المحتوى يدوي.
5. **تنبيهات وتقارير للمدرس**: إحصائيات عن الأسئلة الأكتر تكرارًا من الطلاب
   (بتوريه فين الطلاب محتاجين شرح أكتر)، وده أقوى ميزة ممكن تميز المنصة.

## الدفع الإلكتروني الحقيقي (Paymob) — جديد

بدل "الشراء الوهمي"، المنصة بقى فيها ربط فعلي ببوابة **Paymob** للدفع بالفيزا/
الموبايل. من الإعدادات (⚙️) → "💳 الدفع الإلكتروني (Paymob)" بتكتب:

- **API Key** + **Integration ID** + **Iframe ID** من لوحة Paymob ←
  Developers ← Key Management.
- **HMAC Secret** (مطلوب للتحقق من رسائل البوابة — من غيرها المنصة مش
  هتفتح الدفع للطالب بعد تأكيد نجاحه).
- **وضع الدفع**: محاكاة (افتراضي، من غير فلوس حقيقية) / حقيقي.
- **رابط المنصة (Site URL)**: من أول بطاقة الإعدادات — لازم يبقى رابط
  المنصة الرسمي عشان الطالب يرجع لصفحة النتيجة بعد الدفع.

كيف بيشتغل:

1. الطالب يشحن محفظته أو يشتري حصة → بيتروجّع على صفحة دفع Paymob.
2. Paymob بتبعت تأكيد للـ webhook `/paymob/callback` بتوقيع HMAC، والمنصة
   بتتأكد إن التوقيع سليم قبل ما تفتح الحصة/تشحن المحفظة — مفيش حد بيقدر
   يزوّر "اتدفعت" بدون المفتاح السري.
3. الطالب بيرجع لصفحة "نتيجة الدفع" اللي بتوريه حالة العملية ورقمها.
4. كل طلب دفع متسجل في جدول `payment_orders` بكل بياناته (المبلغ، الحالة،
   رقم عملية Paymob) — تقدر تعمله تقارير/استرداد منها لاحقًا.

> تنبيه: قبل التفعيل الحقيقي، شغّل المنصة على رابط `https` رسمي، وخلي
> `SECRET_KEY` قوية، وعيّن الـ webhook في لوحة Paymob على
> `https://رابطك/paymob/callback`.

## الشحن اليدوي (من غير سجل تجاري ولا بوابة دفع) — جديد

بديل شغال فورًا لو معندكش سجل تجاري: الطالب بيشحن محفظته بنفسه عن طريق
**فودافون كاش / إنستاباي / تحويل بنكي** لرقمك الشخصي، وبعد ما تتأكد إن
الفلوس وصلت، بتدوس "اعتماد" من لوحة الإدارة والرصيد بيتحط للطالب.

- **الإدارة:** من تبويب الفيزا والأرباح → قسم "🕐 شحنات يدوية مستنية" — كل
  شحنة معاها الطالب والطريقة والمبلغ، وزرار اعتماد/رفض. وبتحدد رقمك الشخصي
  من الإعدادات → "رقم استقبال الشحنات اليدوية".
- **الطالب:** من "حسابي" → المحفظة، بيختار طريقة يدوية وبيشوف رقم الاستقبال،
  وبيشوف شحناته المستنية لسه متأكدش الإدارة.
- الحل اليدوي بيشتغل جنب Paymob — لما تفعّل حساب Paymob (فردي/شركة) وتكتب
  المفاتيح، الطرق الآلية (فيزا/فوري/محفظة) هتشتغل أوتوماتيك واليدوية تفضل
  متاحة.

> ملاحظة: الشحن اليدوي بيحتاج ثقة يدوية — تأكد إن التحويل وصل فعلًا لرقمك
> قبل الاعتماد. للأتمتة الكاملة من غير أي تدخل يدوي، استخدم Paymob.

## النشر للانترنت (Deployment)

السيرفر جاهز للنشر على أي استضافة تدعم Docker أو Python/Gunicorn:

### خيار 1: Docker (الأسهل)
```bash
docker build -t thanaweya-platform .
docker run -p 5000:5000 thanaweya-platform
```

### خيار 2: Gunicorn مباشرة (Linux/Ubuntu VPS)
```bash
pip install -r requirements.txt
gunicorn --bind 0.0.0.0:5000 --workers 2 app:app
```
أو على منصات زي Railway/Render: اربط الـ repo ومتنساش `Procfile`
(موجود جاهز) و`gunicorn`.

### خيار 3: تشغيل محلي عادي
```bash
python app.py
```

### إعدادات مهمة قبل النشر
- غيّر `SECRET_KEY` في بيئة التشغيل لسلسلة عشوائية طويلة (افتراضية
  `dev-secret-change-me` مش آمنة).
- غيّر `ADMIN_USERNAME` / `ADMIN_PASSWORD` (بتشتغل أول تشغيل بس).
- حط مفتاح Anthropic من لوحة الإدارة ← الإعدادات، أو بمتغير `ANTHROPIC_API_KEY`.
- قاعدة البيانات `platform.db` + مجلد `uploads/` لازم يكونوا قابلين
  للكتابة (ولو السيرفر بيعمل نسخ احتياطية، مجلد `backups/` كمان).
- المدرسون بيدخلوا بكود (TCH-xxxx) وباسورد عشوائي قوي بيوصلهم على الواتساب،
  وأول دخول بيضطروا يغيّروا الباسورد (فلتر force change).
- لعمل نسخة احتياطية يومية سحابية، تقدر تعمل cron/سكربت يرفع ملفات مجلد
  `backups/` لأي سحابة (Dropbox/Google Drive/S3).

### ملاحظات الاستضافة المهمة
- SQLite كويس للبداية ومتوسط الاستخدام. لو المنصة هتشيل استخدام حقيقي كبير
  أو أكتر من سيرفر، ننقل قاعدة البيانات لـ PostgreSQL.
- الفيديوهات بتتخزن على قرص السيرفر (`uploads/videos/`) — لحجم
  حقيقي، الأفضل تخزين سحابي (S3 / Bunny / Cloudflare R2).
